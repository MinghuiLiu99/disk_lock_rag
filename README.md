# 盘扣架规范 RAG 知识库

面向《建筑施工承插型盘扣式钢管脚手架安全技术标准》JGJ/T 231-2021 的结构感知检索增强问答系统。

与"把 PDF 丢给通用解析器再向量检索"的做法不同，本项目把规范中的**条文、表格、公式、图**当作四类异构单元分别处理，并利用规范内部**显式可溯源的引用关系**做闭包扩展，让答案既准确又能给出法源。

> **当前状态：完整 57 页 PDF 已跑通**——381 个节点、0 校验错误、0 重复 `node_id`，解析耗时 6.8 秒。
> 另有一个 7 页测试件（第 5 章）用于快速回归，产出 72 个节点。

| | 7 页测试件 | 完整 57 页 |
|---|---|---|
| 节点数 | 72 | **381** |
| 解析耗时 | 0.7 s | **6.8 s** |
| 引用边（范围内） | 23（11） | **74（48）** |
| 类型分布 | 1 章 / 5 节 / 21 条 / 4 表 / 1 图 | 9 章 / 19 节 / **153 条** / 91 款 / **20 表** / **13 图** / 22 公式 / 4 附录 / **50 条条文说明** |

条文说明与正文已按条号双向关联，**153 条正文中有 67 条拿到官方说明（44%）**；区间写法（`4.1.1～4.1.4`）与列举写法（`7.4.11、7.4.12`）会自动展开成多条。

## 一、要解决的问题

通用 RAG 管线在这类文档上会系统性失效。下面是同一份 PDF 的实测对比：

| | RAGFlow v0.27.2（laws 预设） | 本项目 |
|---|---|---|
| 分块结果 | 373 块，**93 块不足 10 字**，中位数 38 字 | 72 节点，0 校验错误 |
| 表格 | **79 个纯数字碎片**（表结构完全丢失） | 4 张表全部结构化，合并表头 / 转置表均正确 |
| 公式 | 符号乱码（Symbol 字体私有区编码未处理） | 14 个码位全修复 + 变量表 + 截图 |
| 条文号 | **错位**（6.2.3 的内容被并进标着 6.2.4 的块） | 正确 |

失效的根源不是模型不好，而是**文本块边界与规范的结构边界不一致**：表格被切碎、公式被拆散、条文号被换行截断。一旦切错，后面的检索和生成都无法挽回。

## 二、效果实测

在 7 页测试件上跑过的问法（累计 23 条，通过 22 条）：

| 组别 | 结果 |
|---|---|
| 事实型 / 查表型 / 公式型 / 图形型 / 跨条对比 | ✅ 全部 top-1 命中，答案正确，引用可溯源 |
| 口语化提问（5 条） | ✅ 4/5（"斜撑"失败 → 已用同义词扩展修复） |
| 对抗探针：超范围 / 规范未规定 | ✅ **正确拒答** |
| 对抗探针：枚举型（"本章哪些条文提到 X"） | ❌ 漏答（top-k 检索的固有缺陷） |

**反幻觉是实测有效的。** 探针"扫地杆距可调底座底板不应大于多少"的真实答案 550mm 位于第 6.2.5 条，不在这 7 页内——而 550mm 是模型预训练里大概率知道的常识。系统没有编造，而是拒答。这依赖三层设计：提示词约束、材料中显式标注"引用的附录不在材料范围内"、生成后的引用回查。

性能（本地推理，无 API 成本）：**答案首字 3~4 秒，完整回答 4~14 秒**。

## 三、架构

```
PDF
 └─ 版面解析 ──── 字符坐标聚类 → 表格还原 / 图区定位 / 公式区识别
     └─ 结构重建 ─ 符号修复 · 断行修复 · 跨页合并 · 同号合并 · 表头扁平化
         └─ 节点构建 ─ 26 字段节点 + 父子链 + 引用边 + 质量标记
             └─ 索引 ──── 向量 | BM25 | 表格库 | 引用图
                 └─ 检索 ─ 同义词扩展 → 编号硬加权 → 混合 RRF → 引用闭包扩展
                     └─ 生成 ─ 父子回填 → 带引用约束生成 → 引用回查 → 拒答
                         └─ 前端 ─ 流式答案 + 依据卡片 + PDF 原文坐标高亮
```

### 四类异构单元的处理策略

| 单元 | 检索表示（`content`） | 原文载体（`body`） | 说明 |
|---|---|---|---|
| **条文** | 整条原文 | — | 以"条"为原子单位，不按字符数切；款/项单独成节点 |
| **表格** | 扁平表头 + 行级"列名=值" | 结构化行列 + Markdown + 表注 | 合并表头压成单层，转置表还原语义，纵向合并向下填充 |
| **公式** | 语义句 + "式中"变量表 | 线性文本 + 变量表（+ 截图） | **公式本体不进向量**——符号对 embedding 无意义 |
| **图** | 图题 + 图注 | 按坐标裁切的 PNG | 矢量图靠图元聚类定位，位图接口取不到 |

## 四、快速开始

### 环境

Conda 环境 `rag_env`（Python 3.12），依赖：

```bash
pip install pdfplumber pypdfium2 pillow numpy networkx fastapi uvicorn
```

本地模型通过 LM Studio 的 OpenAI 兼容接口提供（默认 `http://localhost:1234/v1`）：
- embedding：`text-embedding-bge-m3`
- 生成：`qwen3.8-27b-*`（任意可用的中文模型）

### 步骤

```bash
# 1) 解析 PDF → 节点 + 抽检报告
python run_parse.py                       # 默认解析测试件
python run_parse.py --pdf <你的规范.pdf> --offset <页码偏移> --doc-id <标识>

# 2) 建索引 + 跑检索验收（会打印 BM25 / 向量 / 混合 三路对比）
python run_index.py

# 3) 启动问答前端
python app.py                             # 打开 http://127.0.0.1:8000
```

### 在 notebook 里调用

```python
from rag_core import DocumentParser, validate_all, summary, to_jsonl, from_jsonl

parser = DocumentParser("jgj 231-2021_test.pdf", "JGJ231", "JGJ/T 231-2021",
                        "jgj231_2021_ch5_test", "2021",

                        figure_dir="out/figures")

to_jsonl(nodes, "out/nodes.jsonl")
```


## 六、节点字段规范

每个节点 26 个字段，分六组：

| 组 | 字段 |
|---|---|
| 身份 | `node_id` `standard_id` `standard_code` `doc_id` `version` `type` `num` |
| 定位 | `level` `chapter` `section` `path` `pages` `bboxes` |
| 内容 | `content`（检索表示）`body`（原文载体） |
| 关系 | `parent_id` `child_ids` `refs` `referenced_by` `explains` `explained_by` |
| 语义 | `modality`（严禁/必须/应/宜/可）`keywords` `keywords_source` |
| 质量 | `status` `status_reason` |

设计原则：

1. 每个字段只服务于**检索 / 生成 / 溯源**三者之一
2. 抽不到写 `null`，确定为空集合写 `[]`，**禁止空字符串**
3. `content` 与 `body` 分离——前者可以是为检索生成的代理文本，后者是给人看的原文
4. `pages` 记**原书页码**（不是文件内页码），否则无法回溯到完整版 PDF
5. `level` 由 `type` 推导，不手填

## 七、实测发现的 12 类排印陷阱

这些是通用解析器会踩、且踩了之后**不可逆**的问题。全部在 `layout.py` / `parser.py` 里有对应处理，并写进注释。

| # | 陷阱 | 处理 |
|---|---|---|
| 1 | 公式符号是 Symbol 字体私有区编码（本 PDF 14 个码位） | 码位映射表 |
| 2 | 矢量图被表格检测误判为表格（区域内无文字单元格） | 用"有无文字"过滤假阳性 |
| 3 | 跨页表格，表头在上页页尾（只剩 1 行 2 列） | 页尾表头 + 页首表体合并，列数补齐 |
| 4 | 跨页表的**表标题**也在上一页 | 标题随表头一起继承 |
| 5 | 单元格内下标被空格拆开（`G1+G2` → `G 1 +G 2`） | 按字符坐标重建，不用通用抽取接口 |
| 6 | 条文以"（图"结尾断行，下一行行首的 `6.2.4）` 被当成新条文 | 断行修复 + 条号负向断言 |
| 7 | 条文被表格打断，同一段出现两次条号 | 同号合并 |
| 8 | 条文跨页续接（"式中"段落跑到下一页） | 跨页归并到上一条文 |
| 9 | 表注是多行，续行没有"注："前缀 | 从"注："抓到下一条号之前 |
| 10 | 页脚页码混进条文正文 | 页边距区域过滤（页码只进 `pages` 字段） |
| 11 | 图题、图注、子图标签被当成正文 | 归属到图节点，并纳入图区坐标 |
| 12 | 合并表头（`类别 \| 连墙件布置` + `2步3跨 \| 3步3跨`） | 横向传播 + 纵向拼接压成单层表头 |

另外还有三类容易忽略的：

- **转置型表**：表头是"搭设高度"，行首是"βH"，语义方向与常规表相反，需要单独识别
- **表标题粘连**：原文写作"按表5.3.2 支撑脚手架搭设高度调整系数"，需要从粘连文本里拆出标题
- **破折号混用**：图注用 U+FF0D 全角连字符，全文其他地方用 U+2014 长破折号，不归一化会导致精确匹配失败

## 八、工程上踩过的坑

1. **本机 numpy 2.5.3 的 BLAS 在 2D@1D 矩阵向量乘上原生崩溃**（`0xc06d007f`）。改用逐元素乘 + 求和（`(matrix * q).sum(axis=1)`）。
2. **引用图必须包含父子边**。只加 `refs` 边时闭包扩展一条都带不回来——"条文 → 它自带的公式"是父子关系而非引用关系。
3. **枢纽节点不能扩展**。从"节"扩展会把整节条文全拉进上下文，只从内容型节点（条/款/表/图/公式）扩展。
4. **零分的扩展节点会把高分的直接命中挤出上下文**。问"可调托撑承载力"时，表 5.1.9 被 5 条零分扩展条文挤掉，模型只能回答"材料中未规定"。改成两段填充（直接命中优先）+ 分数比例过滤。
5. **编号类查询不能交给向量**。"5.4.2 说了什么"会被语义相近的 5.4.3 抢走，必须加显式标识符硬加权。
6. **带着类型前缀的编号要先遮住再扫裸编号**。"表5.1.9"里的 5.1.9 是表号不是条号，不遮的话条文 5.1.9 也会被加权。
7. **本地生成模型默认"永远思考"**，token 预算会被 reasoning 吃光导致空答案。LM Studio 支持 `reasoning_effort: "none"` 关闭思考（取值必须是 `"none"`，`"off"` 会返回 HTTP 400），首字从 15~26 秒降到 2~4 秒，答案反而更直接。

## 九、当前状态与局限

**已验证可用**

- 完整 57 页：单条事实 / 查表取值 / 公式引用 / 图形识别 / 跨条对比
- **跨章引用闭包**：问"立杆稳定性怎么验算"，可沿 `5.3.3 → 附录C(φ) → 附录B表B.0.2(A,W)` 把整条依赖链带回来
- **一处规定在多条中**：如"插销下沉量"，同时召回基本规定 3.0.2 与安装章节 7.4.7
- 反幻觉与拒答（材料中缺失时拒答，不调用预训练知识）
- 带法源的流式问答 + PDF 原文高亮

**已知不足**

| 问题 | 原因 | 方向 |
|---|---|---|
| 枚举型问题漏答 | top-k 检索的固有缺陷 | 需要"全库过滤"而非相似度召回 |
| **5 张附表内容过长** | 表 D.0.1/D.0.2（35×22 格）各约 4000 字、表 C.0.1/C.0.2（297 格）各 2213 字，而上下文预算只有 3500 字；且系数表的列名是"0~9"，代理文本 `0=1.000` **无语义** | 做成查表工具（值查）+ 模板（验收表），不进向量库 |
| 附录条文展示标签不对 | 现在显示"第B.0.1条" | 应显示"附录B.0.1" |
| 主题不匹配未识别 | 问"**扣件式**脚手架…"会用**盘扣式**条文回答 | 需要标准适用范围校验 |
| 没有系统的准确率 / 召回率 | 只有手工冒烟 | 需配评测集 |
| 同义词表需人工维护 | 目前 13 组手工词对 | 可用规范自带的 2.1 术语章节做半自动种子 |
| 多规范冲突未处理 | 如可调托撑悬臂：JGJ/T 231 为 650mm、DB11/T 2100 为 500mm | 需要标准优先级规则 |

**尚未验证**：多标准泛化、扫描版 PDF、长上下文（LM Studio 当前 loaded_context_length 仅 8192）。
